# 마진가드 (MarginGuard)

**반대매매 한계선 사전 진단** — 2026 금융 AI Challenge 출품작.
약관을 읽는 AI(구조화 추출·개정 감지)와 결정론 리스크 엔진(임계가 역산·처분 수량 산정)의 결합. **계산은 LLM이 하지 않는다** — 이것이 이 제품의 핵심 주장이다.

> 전략·검증 문서(기획서, 판정서, HANDOFF)는 이 repo에 넣지 않는다. 팀 공유 폴더가 정본. 이 repo는 **코드만**.

### 5-B. 서승기 — AI 인제스트 · 🔴 게이트의 본체

**게이트 3항목이 전부 여기 하나에 걸려 있다.** 다른 트랙이 다 통과해도 이게 없으면 *"AI가 어디 있나"* 에 답할 화면이 없다.

`POST /ingest`의 2패스 추출 경로를 구현했다. ①평탄화 문서를 citations와
`cache_control`로 보내 native `char_location`을 확보하고, ②검증된 citation
목록만 structured output에 넘겨 `ConditionCard(draft)`를 만든다. 원문 전체는
2패스에 다시 보내지 않는다.

반환 전에 반드시 다음을 모두 통과한다.

1. citation의 `cited_text`가 평탄화 원문의 `char_start:char_end`와 축자로 일치
2. 2패스의 모든 evidence가 1패스 citation과 필드 전체가 일치
3. JSON Schema Draft 7 검증
4. `ConditionCard.model_validate` 수치·좌표·해시 검증
5. 설명 필드의 산식·계산 결과 혼입 거부 및 `status=draft` 강제
6. 심사필 번호는 native citation에서 서버가 추출하고, 없으면 업로드 원문
   바이트 SHA-256을 `content_sha256`으로 주입 (`doc_version`은 LLM 출력 금지)

실행 시간과 토큰 사용량은 `X-Ingest-*` 응답 헤더로 기록한다. 실제 한투 1건
유료 종단 실행은 2026-08-16에 완료했고, 재현 가능한 결과를
`services/ingest/benchmarks/results/hankook_two_pass.json`에 기록했다.

```powershell
cd services/ingest
# dry-run: 네트워크 0회, 원문·프롬프트 해시와 예상 최대 비용만 출력
.\.venv\Scripts\python.exe -m benchmarks.hankook_two_pass

# 실제 실행: dry-run의 estimated_max_cost_krw 이상을 명시해야만 호출
.\.venv\Scripts\python.exe -m benchmarks.hankook_two_pass `
  --execute --approve-max-krw <승인금액>
```

승인 상한은 가격 인하 종료 뒤에도 과소 추정되지 않도록 표준가 `$3/$15`
(입력/출력, MTok당)로 계산한다. 실행 결과에는 usage를 표준가와 2026-08-31까지의
도입가 `$2/$10`으로 각각 환산해 기록한다. Messages API는 실제 청구액을 반환하지
않으므로 콘솔에서 확인하기 전 `console_billed_cost_krw`는 `null`이다.

`cache_control`은 같은 문서와 같은 `prompt_sha256`을 5분 안에 다시 호출할 때만
절감 효과가 있다. 프롬프트가 바뀐 최초 실행은 cache write이고, 결과의
cache read 토큰이 0이면 절감이 발생했다고 보고하지 않는다.

## 6. 규약 — 트랙·Phase와 무관하게 유지되는 것

여기 있는 것은 과업이 아니라 **규칙**이다. Phase가 끝나도 사라지지 않는다.

### 6-1. TR_ID 가드 — 누구도, 어떤 이유로도 제거 금지 (C)

KIS는 **도메인만 바꾸면 실계좌로 주문이 나간다.** 단순 `V` prefix 검사가 아니라 **레지스트리 기반 deny-by-default**다(이슈 #4에서 정정 — 시세 `FHKST01010100`은 실전·모의 공용이라 V 변형이 없다).

① 우리가 쓰는 TR_ID를 `{용도, 카테고리(transactional|market_data), 실전ID, 모의ID}` 레지스트리에 등록 — **레지스트리에 없는 TR_ID는 환경 불문 차단**
② `KIS_ENV=vps`: transactional은 모의(V계열)만, market_data는 공용 F계열 허용
③ `KIS_ENV=prod`: **transactional 전면 차단** — 대회 기간 실전 거래는 어떤 경우에도 없다(실전 키는 시세 백업 전용)
④ 도메인·TR_ID를 `KIS_ENV` 한 곳에서 파생시켜 셋이 어긋날 수 없게

구현: `apps/web/lib/kis/guard.ts` + 카테고리별 차단 단위 테스트.

### 6-2. 4중 방어 — 순서대로 (B)

① **모든 수치에 근거 좌표**(페이지+스팬+인용) — 좌표를 못 찾으면 **카드 전체 거부**
② `schemas/condition_card.schema.json` 검증(jsonschema) + Pydantic
③ 수치 범위 (r 1.0~2.0, h 0~0.35)
④ 출력에 산식·계산이 섞이면 거부 — **LLM은 읽고 인용만 한다. 계산은 엔진만 한다**

인제스트 출력의 `status`는 **무조건 draft**다. verified 승격은 사람 검수 후.
모델은 **claude-opus-5** 권장 — 근거 좌표 정확도가 이 팀의 생사라 여기서 모델을 아끼지 않는다.

### 6-3. API 키 정책 — 개발은 구독으로, 런타임만 API로


**추가 비용을 쓰지 않는 것이 팀 방침이다.** 아래 3층으로 나눈다.

| **프롬프트 개발·반복** (작업량의 90%) | **Claude Code CLI 헤드리스** — `claude -p "..." --output-format json --json-schema '...'`. 구독으로 동작하고 스키마 검증 출력까지 지원한다. 프롬프트 튜닝·표 재현율 비교·골든 대조를 전부 여기서 한다 | **0원** |

- **CLI를 서비스 백엔드로 쓰는 것은 금지에 해당한다.** Agent SDK 문서 명문: *"Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products."* 심사위원 요청을 우리 구독으로 처리하는 건 정확히 이 경우다. **배포 백엔드는 API 키만 쓴다.**


### 6-4. 근거 좌표 — citations를 쓴다. 2패스로 확정


document 블록에 `citations: {enabled: true}`를 켜면 응답이 **`cited_text` + 위치**를 네이티브로 돌려준다. LLM에게 좌표를 자가 보고시키는 것보다 신뢰도가 훨씬 높다 — 4중 방어 ①의 근본 해법이므로 **citations를 쓴다.**

**⚠ 입력 형태가 좌표 형태를 결정한다 — 이게 1~2일차 스파이크의 진짜 쟁점이다.**

수집물은 **HTML 2건(한투·유진) + PDF 5건**이다. 따라서 입력 형태는 세 갈래다.
*(초판에서 pypdf/PDF 두 갈래로만 적었던 것을 정정 — 한투 원문이 `.htm`이라 어느 쪽에도 해당하지 않았다. 이슈 #7 참조)*

| document 블록에 넣는 것 | citations가 주는 위치 | 현행 `EvidenceSpan` |
|---|---|---|
| **HTML 평탄화 텍스트** (한투·유진) | **`char_location`** — `start_char_index` / `end_char_index` | **`page`(필수, ≥1)를 채울 값이 없다** → 스키마 PR 필요 |
| **pypdf 추출 텍스트** (PDF 5사) | **`char_location`** | `start`/`end`는 맞으나 `page`는 pypdf가 별도로 알려줘야 함 |
| **PDF 원본** (base64) | `page_location` — `start_page_number` / `end_page_number` (1-indexed) | `start`/`end`를 못 채움 → 스키마 PR 필요 |

즉 파싱 스파이크는 품질 비교가 아니라 **어느 좌표계로 통일할지를 정하는 작업**이다. HTML이 이미 섞여 있으므로 **`page` 필수 제약은 어느 경로를 골라도 완화가 필요하다.**

**스키마 방향 (A 선승인 + D 조정, 이슈 #7):**
- `quote` + `source_format`(`"pdf" | "text" | "html"`) **필수**
- 위치는 **anyOf** — 페이지형(`page`/`end_page`) 또는 문자형(`char_start`/`char_end`)
- **카드 하나 안에서는 한 형태로 통일** (섞이면 UI 하이라이팅이 두 경로를 다뤄야 함)

> anyOf로 두는 이유: A의 원안(`char_start`/`char_end` 공통 필수)은 텍스트 정규화 경로에선 더 엄격해서 좋지만, **PDF 원본 경로는 char 오프셋이 아예 없어 그 경로를 막는다.** 스파이크 결과 텍스트 정규화로 통일되면 그때 문자형만 남기고 조여도 된다 — 지금 조이면 아직 열려 있는 선택지를 닫는다.

스키마 변경은 경계 타입이므로 **PR + 전원 승인**이고, 세 미러(`types.ts` / `condition_card.schema.json` / `schemas.py`)를 함께 고친다.

**파이프라인은 2패스로 확정한다.** citations는 `output_config.format`(structured outputs)와 **병용 불가 — 400이 문서에 명시**돼 있다. 그러므로 ①1패스에서 citations로 인용·좌표 확보 → ②2패스에서 구조화. strict tool use로 1패스가 되는지는 **최적화 항목**이지 블로커가 아니다 — 2패스로 먼저 세우고, 나중에 확인해서 되면 줄인다.


### 6-5. 배포 신선도 확인 — "살아 있다"와 "올바르다"는 다르다


배포가 조용히 뒤처지는 일이 **두 번** 있었다(#10 직후, #14 직후). 두 번 다 URL은 200을 줬다.
**옛 커밋을 서빙하는 배포도 200을 준다.** 그래서 헬스체크가 상태코드에서 멈추면 안 된다.

```bash
curl -s https://marginguard-web.vercel.app/api/build
# {"sha":"…","shortSha":"f27a972","branch":"main","source":"vercel"}
```

`shortSha`가 `git rev-parse --short main`과 다르면 **배포가 뒤처진 것**이다. 푸터에도 같은 값이 찍힌다.

- 화면의 특정 문구로 판별하지 말 것. 문구는 화면이 바뀔 때마다 기준을 다시 정해야 하고,
  실제로 `'같은 부족액, 회사만 다를 때'`는 **신·구 양쪽에 다 존재해서** 판별에 쓸 수 없었다.
- `branch`도 같이 본다 — **프리뷰 URL을 프로덕션으로 착각하는 사고는 SHA가 아니라 브랜치명이 막는다.**
- W5 무중단 리허설의 무인 헬스체크는 이 엔드포인트를 기준으로 짠다.

### 6-6. 정수 스케일 — 비율 곱을 부동소수로 풀지 말 것 (A)

`r`·`h`가 걸린 곱은 **정수 스케일**(`r×100`, `h×10000`)로 환산해 계산한다. `packages/engine`의
`shortfall`·`restorationCoefficient`가 그렇게 돼 있고, **풀지 말 것.**

근거는 이 곱이다:

```
1.4 × 5,500,000 = 7,699,999.999999999   (IEEE754)
1.4 × 6,000,000 = 8,400,000             (오차 0)
```

**오차 방향이 D 과소 = 처분 수량 과소 = 낙관이다.** "소수점까지 재현"을 내건 제품에서
가장 위험한 방향으로 틀어진다.

⚠ **이 규약은 오래 검증되지 않은 채로 있었다.** 골든이 8건인데 L 분포가 이렇다(실측):

```
L=6,000,000  kis-case1-full · kis-case2-partial · kis-ratio-series
L=5,500,000  samsung-h15-partial · samsung-h20-full     ← 정수 스케일 가드
(L 없음)     meritz-h20 · lower-limit-fallback · voluntary-sale-96
```

**삼성 2건이 들어오기 전까지는 naive float로 바꿔도 골든이 전부 통과했다.** 이 문서도 한동안
`1.4 × 6,000,000`을 근거로 들었는데, 그 곱은 오차가 0이라 근거가 될 수 없었다(#21에서 A가 정정).
**규약이 테스트로 지켜지고 있는지와 규약이 옳은지는 다른 질문이다.**

## 7. 협업 규칙

1. **브랜치**: `main` 직접 push 금지(이 초기 스캐폴드 제외). `feat/{역할소문자}-{주제}` (예: `feat/a-replay-sim`). PR 리뷰 1인 이상, **엔진 변경은 A 포함 2인**.
2. **골든 테스트를 깨는 커밋은 merge 금지** — CI가 막는다. 기대값 수정은 원문 출처 첨부 + 2인 승인.
   CI는 **테스트 · 빌드 · 린트** 3개 잡을 돌린다. 린트는 장식이 아니다 — `react-hooks/refs`가 테스트가 전부 green인 채로 남아 있던 **동작 버그**(재생 중에도 버튼이 활성으로 보이던 문제)를 실제로 잡아냈다.
3. **커밋 메시지**: `[A|B|C|D] 요약` (예: `[B] 근거좌표 누락 시 카드 거부 로직`).
4. **경계 타입 변경 = PR + 전원 승인.** B는 JSON Schema·Pydantic 동기화 책임.
5. **비밀키·계좌번호 커밋 금지.** 유출 시 즉시 재발급 + 팀장 보고.
6. **산식·수치 변경은 출처(문서·조항) 필수.** 출처 없는 수치는 코드에도 못 들어온다.
7. **문서 개정 금지** — 진척은 코드로만 측정한다. 기획서를 고치고 싶어지면 멈출 것.

## 8. 심사 기간(9/7~9/11) — 무중단과 비용을 동시에

심사 기간에는 두 요건이 충돌한다: **배포 URL 5일 무중단**(결격 사유)과 **추가 비용 최소화**. 아래 설계로 둘 다 만족시킨다.

### 원칙: 기본 경로는 API를 호출하지 않는다

| 화면 | 동작 | 런타임 API 호출 |
|---|---|---|
| 랜딩(역산 슬라이더) + 계기판 | 스냅숏 데이터 + 클라이언트 엔진 | **0** |
| 조건 카드 조회 | **사전 계산·커밋된 카드**(7사+) | **0** |
| 약관 풀 선택 데모 | 미등록 증권사 풀에서 선택 → 커밋된 draft 카드 | **0** |
| **임의 약관 업로드** | 심사위원이 올린 그 순간만 | 건당 1회 |

심사위원 대부분은 앞의 세 줄에서 끝난다. **API가 도는 건 마지막 한 줄뿐**이고, 5일간 수십 회 수준이면 비용은 만원 이하다.

### 자택 서버 + Claude Code CLI 백엔드를 쓰지 않는 이유

1. **금지 규정에 해당한다.** Agent SDK 문서 명문 — *"Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products."* 심사위원 트래픽을 팀원 구독으로 처리하는 것이 정확히 이 경우다.
2. **무중단 요건과 정면 충돌.** 노트북 절전·와이파이 끊김·정전·터널 URL 만료·구독 사용량 한도 — 어느 하나만 걸려도 심사 중 데모가 죽는다. 이건 결격이고, 절약액보다 비교할 수 없이 크다.
3. **보안 역행.** 우리는 심사위원에게 **임의 PDF 업로드를 권한다**(4중 방어 ④가 그 대비다). 도구(bash·파일 접근)를 가진 에이전트 하네스를 신뢰할 수 없는 PDF에 물리는 건, 도구 없는 순수 API 호출보다 공격면이 넓다. 오염 방어를 자랑하는 팀이 오염 경로를 넓히는 셈이 된다.

### 하드 가드 (C 구현, W5)

- **Console에 spend limit을 건다** — 상한을 넘어도 서비스가 죽지 않고 업로드 기능만 참고 모드로 강등되게 처리
- **업로드 엔드포인트에 레이트 리밋** — IP·세션당 상한 (오남용·사고성 반복 호출 차단)
- **잔액 알림** — 9/6에 잔액 확인 + 여유분 충전을 D-day급 체크 항목으로 (크레딧이 떨어지면 *"AI가 어디 있나"에 답하는 바로 그 데모*가 죽는다)
- **프롬프트 캐싱** — 약관 본문을 캐시 프리픽스로 두면 같은 문서 반복 호출의 입력 비용이 ~10%로 떨어진다
