# 마진가드 (MarginGuard)

**반대매매 한계선 사전 진단** — 2026 금융 AI Challenge 출품작.
약관을 읽는 AI(구조화 추출·개정 감지)와 결정론 리스크 엔진(임계가 역산·처분 수량 산정)의 결합. **계산은 LLM이 하지 않는다** — 이것이 이 제품의 핵심 주장이다.

> 전략·검증 문서(기획서, 판정서, HANDOFF)는 이 repo에 넣지 않는다. 팀 공유 폴더가 정본. 이 repo는 **코드만**.

| 역할 | 담당 | 오너십 | 이 역할이 지키는 방어선 |

| **B — AI 파이프라인** | **신승기** | 약관 인제스트(PDF→조건카드+근거좌표), 개정 diff, 오염 방어 | **"AI가 어디 있나"** — 이 팀의 생사가 걸린 데모 |

> **발표자(2차 심사 연사)는 미정.** D는 발표 *자료*의 오너일 뿐 발표자와 별개다. 발표자는 늦어도 **8/24 판정선 회의**에서 결정한다 — 2차는 본선 진출 발표(9/22) 이후지만, 리허설 시간을 확보하려면 그 전에 정해야 한다. QA 답변은 어차피 전원이 자기 트랙(A 산식 / B AI / C 인프라 / D 법·제품)을 직접 받는 게 강하다.

**경계 계약**: A↔D는 `RiskResult`, B↔A는 `ConditionCard`, C↔A는 `Position`/`CreditLedger` 타입으로 격리 — 전부 [packages/engine/src/types.ts](packages/engine/src/types.ts)에 이미 정의돼 있다. **변경은 PR + 전원 승인.** 이 계약 위에서 4인이 목(mock)으로 병렬 작업한다.

| Day | 작업 | 상세 |
|---|---|---|
| 1~2 | **엔진 적대 검증** | `packages/engine`은 검증된 산식으로 구현돼 있고 테스트가 green이다. **믿지 말 것.** 한투 신용거래 설명서 원문과 한 줄씩 대조해 깨뜨려 볼 것. 특히 ① `k = r(1−h) − 1`에 **f가 없는 이유**(f는 미수·자발매도 산식 전용 — 섞으면 195→206주. 회귀 테스트로 박제돼 있음) ② 세 가격 구분(평가 8,100 / 산정 6,885 / 체결 7,000 — 체결가는 수량 산정에 미관여) ③ 부동소수 처리(1.4×6,000,000 ≠ 8,400,000이라 정수 스케일 계산을 쓴다 — 풀지 말 것) |

| Day | 작업 | 상세 |
|---|---|---|
| 1 | **환경** | `services/ingest` 기동(위 빠른 시작), `/health` 200 확인. `ANTHROPIC_API_KEY` 발급(.env) |

| 2~5 | **구조화 추출 v0** | Claude API(**claude-sonnet-5** 권장)로 8항목 추출 → `/ingest` 구현. **4중 방어 순서대로**: ① 모든 수치에 근거 좌표(페이지+문자 스팬+인용) — 좌표를 못 찾으면 **카드 전체 거부** ② `schemas/condition_card.schema.json`으로 검증(jsonschema) + Pydantic ③ 수치 범위(r 1.0~2.0, h 0~0.35) ④ 출력에 산식·계산이 섞이면 거부 — **LLM은 읽고 인용만 한다. 계산은 엔진만 한다** |

### 5-C. 이예찬 — 플랫폼/연동

**목표 한 줄**: KIS 모의 API를 BFF 프록시로 관통시키고, Next.js 앱과 배포 파이프라인을 세운다.

| Day | 작업 | 상세 |
|---|---|---|
| 1 | **Next.js 생성** | repo 루트에서 `npx create-next-app@latest apps/web --ts --app --eslint` (Tailwind는 D와 상의해 선택). 생성 후 루트에서 `npm install`로 워크스페이스 연결 확인 |
| 1~2 | **TR_ID 가드 (최우선·필수)** | KIS는 도메인만 바꾸면 **실계좌로 주문이 나간다.** 단순 `V` prefix 검사가 아니라 **레지스트리 기반 deny-by-default**로 구현한다(이슈 #4에서 정정 — 시세 `FHKST01010100`은 실전·모의 공용이라 V 변형이 없음): ① 우리가 쓰는 TR_ID를 `{용도, 카테고리(transactional\|market_data), 실전ID, 모의ID}` 레지스트리에 등록 — **레지스트리에 없는 TR_ID는 환경 불문 차단** ② `KIS_ENV=vps`: transactional은 모의(V계열)만 허용, market_data는 공용 F계열 허용 ③ `KIS_ENV=prod`: **transactional 전면 차단**(대회 기간 실전 거래는 어떤 경우에도 없다 — 실전 키는 시세 백업 용도뿐), market_data만 허용 ④ 도메인·TR_ID를 `KIS_ENV` 한 곳에서 파생시켜 셋이 어긋날 수 없게. **이 가드는 누구도, 어떤 이유로도 제거 금지.** `apps/web/lib/kis/guard.ts` + 단위 테스트(카테고리별 차단 케이스 포함) |
| 2~4 | **BFF 프록시** | `/api/kis/*` 라우트로 KIS 4엔드포인트 관통: **토큰 발급 → 국내주식 시세 → 매수가능조회 → 잔고**. 프록시가 필수인 이유: KIS는 CORS preflight에 501을 던져 브라우저 직접 호출이 100% 불가. 구현 요건 — ① 토큰 캐시(24h 유효, 재발급 6h 제한 규칙 준수: 파일/메모리 캐시로 중복 발급 차단) ② **레이트리미터 큐**(모의는 초당 1건 — 화면 하나에서 병렬 호출하는 설계는 즉시 깨진다. 큐 + 100~150ms 텀 + `EGW00201` 백오프) |
| 4~6 | **배포·CI** | Vercel 프로젝트 연결(apps/web), 프리뷰 URL 발급. CI는 이미 있음(.github/workflows/ci.yml) — apps/web 빌드 잡 추가. **웹소켓은 Phase 2** (KIS는 ws만 지원 → HTTPS 페이지에서 Mixed Content 차단 → 서버 중계 필요하다는 것만 미리 알아둘 것) |

**DoD**: 로컬 `/api/kis/*` 경유 모의 시세 응답 + TR_ID 가드 테스트 green + Vercel 프리뷰 URL.
**합성 신용 원장**(융자금 L·이자는 우리 장부 — 모의 API는 신용 미지원)은 Phase 2에서 A와 함께. Phase 1은 배관만.

## 6. 협업 규칙

1. **브랜치**: `main` 직접 push 금지(이 초기 스캐폴드 제외). `feat/{역할소문자}-{주제}` (예: `feat/a-replay-sim`). PR 리뷰 1인 이상, **엔진 변경은 A 포함 2인**.
2. **골든 테스트를 깨는 커밋은 merge 금지** — CI가 막는다. 기대값 수정은 원문 출처 첨부 + 2인 승인.
3. **커밋 메시지**: `[A|B|C|D] 요약` (예: `[B] 근거좌표 누락 시 카드 거부 로직`).
4. **경계 타입 변경 = PR + 전원 승인.** B는 JSON Schema·Pydantic 동기화 책임.
5. **비밀키·계좌번호 커밋 금지.** 유출 시 즉시 재발급 + 팀장 보고.
6. **산식·수치 변경은 출처(문서·조항) 필수.** 출처 없는 수치는 코드에도 못 들어온다.
7. **문서 개정 금지** — 진척은 코드로만 측정한다. 기획서를 고치고 싶어지면 멈출 것.
